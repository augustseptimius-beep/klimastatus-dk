# Phase 1: Project Foundation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up the complete project skeleton — Next.js app, full database schema (all 17+ entities), Docker containerization, and deployment pipeline to Hetzner — so that all subsequent phases build on a running system.

**Architecture:** Monolithic Next.js 15 App Router application with PostgreSQL database. All entities from the datamodel document are created upfront. Docker Compose runs three containers (app, Postgres, Caddy). GitHub Actions deploys on push to main.

**Tech Stack:** Next.js 15, TypeScript, Tailwind CSS v4, shadcn/ui, PostgreSQL 16, Drizzle ORM, Vitest, Docker Compose, Caddy, GitHub Actions.

### Task 21: GitHub Actions deployment workflow

- [ ] **Step 1: Create `.github/workflows/deploy.yml`**

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to GitHub Container Registry
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: docker/Dockerfile
          push: true
          tags: ghcr.io/${{ github.repository }}:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Deploy to server
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /opt/klimastatus
            docker compose -f docker-compose.prod.yml pull app
            docker compose -f docker-compose.prod.yml up -d
            docker image prune -f
```

Note: Secrets (`SERVER_HOST`, `SERVER_USER`, `SERVER_SSH_KEY`, `DB_PASSWORD`) must be added to the GitHub repo settings before the first deploy. This will be set up when the Hetzner server is provisioned.

## Infrastructure Setup Guide (for user)

These steps require the user to create accounts and configure services. They are not code tasks — they're done in a browser.

### Hetzner Cloud

1. Go to hetzner.com/cloud and create an account
2. Create a new project called "klimastatus"
3. Add an SSH key (Claude can generate one if needed)
4. Create a CX22 server (2 vCPU, 4 GB RAM, €4.35/mo) in Falkenstein, Debian 12
5. Note the server IP address
6. SSH in and install Docker:
   ```bash
   ssh root@<SERVER_IP>
   apt update && apt install -y docker.io docker-compose-plugin
   mkdir -p /opt/klimastatus
   ```

### Cloudflare DNS

1. Create a free Cloudflare account
2. Add klimastatus.dk as a site
3. At One.com, change name servers to the ones Cloudflare provides
4. In Cloudflare DNS, add:
   - A record: `klimastatus.dk` → `<SERVER_IP>` (proxy off for now)
   - A record: `*.klimastatus.dk` → `<SERVER_IP>` (proxy off for now)

### GitHub Secrets

Add these secrets to the GitHub repo settings:
- `SERVER_HOST`: the Hetzner server IP
- `SERVER_USER`: `root`
- `SERVER_SSH_KEY`: the private SSH key
- `DB_PASSWORD`: a strong random password for PostgreSQL
